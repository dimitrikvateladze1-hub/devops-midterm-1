# Git Notes

`--force-with-lease` is safer than `--force` because it only overwrites the remote branch if it still points to the commit we last fetched, so it refuses to push if someone else has pushed new work in the meantime instead of silently deleting their commits. Rebase should not be used on shared or public branches (like `main`) that other people have already based work on, because it rewrites commit history and forces everyone else to fix their local copies. For the team from the "Value Stream and DORA metrics" task, trunk-based development fits better than Gitflow: their biggest problems are long waits and only about 2 deploys per week, and short-lived branches merged into `main` frequently with automated CI checks reduce waiting and batch size, while Gitflow's long-lived develop/release branches would add even more delay.
